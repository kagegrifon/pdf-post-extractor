# PDF Post Extractor — дизайн

Дата: 2026-09-29
Статус: согласован в обсуждении, ожидает ревью спеки

## 1. Цель

Офлайн-PWA, которое принимает пачку PDF-бланков конвертов Почты России и собирает один
PDF для печати. На каждом листе — таблица: реквизиты отправления (отправитель, получатель,
трек) и рядом фрагмент бланка с QR-кодом, маркой и штрихкодом. После печати фрагменты
вырезаются и сдаются на почте.

**Критерий успеха:** распечатанный и вырезанный фрагмент принимают на почте, штрихкод и QR
уверенно считываются сканером.

**Исходная проблема:** при ручных скриншотах фрагмент пересэмплировался (зазубрины,
крапинки), и на почте его не принимали.

## 2. Входные данные (проверено на `data/*.pdf`)

- 1 страница, 623.6 × 311.8 pt (≈ 220 × 110 мм), генератор `pdf-lib`.
- Реквизиты — текстовый слой (шрифт Roboto) с координатами, OCR не нужен.
- QR + марка («РОССИЯ·RUSSIA ПОЧТА ₽ 97.00», дата, индекс, код) — растр 980×350 px,
  RGB, FlateDecode (без потерь), bbox x 376–574.4, y 12.9–83.8 pt (от верха страницы).
- Штрихкод — растр 848×1 px, растянут по высоте, bbox x 406–547, y 105.2–149.2 pt.
- Трек под штрихкодом — векторный текст (14 цифр), bbox x 433.6–520.7, y 150–163.3 pt.
- Индекс получателя продублирован шрифтом `PostIndex` с префиксом `$` (крупные цифры
  внизу слева) — его игнорируем.
- Фон бланка (линии, подписи полей) — растр 1247×624 на всю страницу.

**Вывод:** исходник чистый и без потерь. Качество обеспечивается тем, что фрагмент
**не растрируется**: он переносится в итоговый PDF как Form XObject исходной страницы
с обрезкой.

## 3. Решения

| Вопрос | Решение |
|---|---|
| Форма приложения | PWA, работает офлайн, без сервера; файлы не покидают устройство |
| Стек | Vite + TypeScript, без UI-фреймворка |
| Чтение PDF | `pdfjs-dist` (текст с координатами, превью) |
| Сборка PDF | `pdf-lib` (`embedPage` с `boundingBox`, встраивание шрифта через `@pdf-lib/fontkit`) |
| Итоговый формат | PDF (сохраняет исходное качество фрагмента) |
| Обновления | `vite-plugin-pwa`, `registerType: 'prompt'` |
| Хостинг | любой статический (например, GitHub Pages) |
| Тесты | Vitest |

## 4. Архитектура

```
src/
  template.ts   — описание формата бланка (данные)
  extract.ts    — PDF → Shipment | ошибка
  layout.ts     — Shipment[] + пресет → раскладка страниц (чистая функция)
  render.ts     — раскладка + исходные PDF → итоговый PDF
  presets.ts    — пресеты раскладки
  ui/           — DOM-интерфейс
  pwa.ts        — регистрация SW и плашка обновления
```

### 4.1 `template.ts`

Шаблон бланка — чистые данные, без логики:

```ts
interface BlankTemplate {
  id: string;                         // 'russian-post-envelope-v1'
  pageSize: { width: number; height: number }; // pt, допуск ±1 pt
  zones: {
    sender: Rect;                     // левая верхняя область
    senderIndex: Rect;
    recipient: Rect;                  // правая нижняя область
    recipientIndex: Rect;
    track: Rect;                      // под штрихкодом
  };
  crop: Rect;                         // вырезаемый фрагмент
}
```

Все `Rect` — в pt, начало координат в левом верхнем углу страницы (внутри `render.ts`
пересчитываются в систему PDF с началом внизу).

Начальное значение `crop`: x 366–584, y 8–166 pt (≈ 76.9 × 55.7 мм). Оно включает QR,
марку, штрихкод, цифры трека и поле тишины ≥ 3 мм слева и справа от штрихкода. Нижняя
граница ограничена текстом получателя (начинается с y ≈ 167). **Точные значения
подтверждаются на этапе реализации рендером фрагмента всех трёх примеров.**

Новый вид бланка — новый объект шаблона; `extract` перебирает шаблоны и берёт первый
подошедший.

### 4.2 `extract.ts`

```ts
interface Party { name: string; address: string; index: string }
interface Shipment {
  id: string;            // уникальный id в сессии
  fileName: string;
  templateId: string;
  sender: Party;
  recipient: Party;
  trackNumber: string;   // 14 цифр
  pdfBytes: Uint8Array;  // исходник для render
}
type ExtractResult = { ok: true; shipment: Shipment } | { ok: false; fileName: string; error: ExtractError };
```

Алгоритм:
1. Открыть через pdf.js. Ошибка открытия / пароль → `unreadable` / `encrypted`.
2. Страниц ≠ 1 → `unsupported-pages`.
3. Подобрать шаблон по размеру страницы; не нашли → `unknown-format`.
4. `getTextContent()`, у каждого текстового элемента берём координаты и шрифт, элементы
   шрифта `PostIndex` отбрасываем.
5. Распределить элементы по зонам (по пересечению bbox с зоной). Внутри зоны строки
   сортируются сверху вниз, затем слева направо. Первая строка зоны — имя, остальные,
   через пробел — адрес (пример 3: адрес на 2 строках, вторая начинается левее, x = 342).
6. Трек — текст в зоне `track`, совпадающий с `/^\d{14}$/`.
7. Валидация: трек найден, имя отправителя и получателя не пустые, индексы — 6 цифр.
   Иначе → `unknown-format` с пояснением, что не найдено.

### 4.3 `presets.ts` и `layout.ts`

```ts
interface LayoutPreset {
  id: string; title: string;
  page: { width: number; height: number };   // мм
  margins: number;                           // мм, ≥ 5
  columns: number;
  cellGap: number;                           // мм, место под рез
  fragmentScale: number;                     // 1.0 = натуральная величина
  fontSize: number;                          // pt
  printNumberOnFragment: boolean;
}
```

Число рядов **вычисляется**: `floor((pageHeight − 2·margins + gap) / (cellHeight + gap))`,
где `cellHeight` = высота фрагмента × `fragmentScale`. Если в строке не помещается даже
одна ячейка — ошибка пресета.

Начальные пресеты:
- **«A4 альбом, 2 колонки»** (по умолчанию): 297 × 210 мм, поля 7 мм, ожидается 2 × 3 = 6
  на лист, текстовая колонка ≈ 60 мм.
- **«A4 книжная, 1 колонка»**: 210 × 297 мм, поля 5 мм, ожидается 5 рядов (запас ≈ 1 мм;
  если после уточнения `crop` не влезет, будет 4 — это считает формула, а не хардкод).

`fragmentScale` по умолчанию 1.0. Уменьшение допускается только осознанно, UI показывает
предупреждение про сканируемость.

`layout(shipments, preset)` возвращает `Page[]`, каждая `Page` — список ячеек с
абсолютными прямоугольниками: `textRect`, `fragmentRect`, `cutRect` в pt. Модуль не знает
про PDF и тестируется отдельно.

Размеры и плотность ожидаемо поменяются после показа результата пользователю: меняется
пресет, код не трогается.

### 4.4 `render.ts`

- Новый `PDFDocument`, встроенный Roboto (подмножество глифов, кириллица).
- Для каждого исходника один раз вызывается `embedPage(srcPage, boundingBox = crop)`,
  фрагмент рисуется `drawPage` в `fragmentRect` с масштабом `fragmentScale`.
  **Растеризации нет:** в выходном файле лежат исходные потоки картинок.
- Текстовая ячейка: `№`, трек, «Отправитель: имя, адрес, индекс», «Получатель: …»,
  с переносом по ширине `textRect`; при переполнении текст обрезается с «…».
- Пунктирные линии реза по `cutRect` вокруг фрагмента, за пределами поля тишины.
- Если `printNumberOnFragment`, мелкий номер строки (6 pt) в углу вырезаемой области,
  вне поля тишины штрихкода.
- Метаданные: title «Отправления YYYY-MM-DD», имя файла `otpravleniya-YYYY-MM-DD.pdf`.

### 4.5 UI (`ui/`)

Один экран:
- Drop-зона и кнопка «Выбрать файлы»; файлы можно добавлять порциями.
- Список: имя файла, статус (✓ / текст ошибки), трек, получатель, кнопка удаления.
  Порядок меняется перетаскиванием; он же — порядок в итоговом PDF.
- Повтор трека — предупреждение у обоих файлов (в итог попадают оба, решает пользователь).
- Выбор пресета.
- Превью итогового PDF (`<iframe>` с blob URL, встроенный просмотрщик браузера).
- «Скачать PDF» и «Печать» (печать — через тот же iframe). Обе неактивны, если нет ни
  одного годного файла.
- Постоянная подсказка: **«Печатайте в масштабе 100% (не „по размеру страницы“)»**.
- Футер: версия приложения (из `package.json` через `define`).

### 4.6 PWA и обновления (`pwa.ts`)

- `vite-plugin-pwa`, Workbox precache всех ассетов, включая worker pdf.js и шрифт.
- `registerType: 'prompt'`: при наличии новой версии показывается плашка «Доступна новая
  версия — Обновить». По клику — `updateSW(true)`, перезагрузка. Молча не перезагружаем,
  чтобы не потерять загруженную пачку.
- Проверка обновления при запуске и раз в час, пока приложение открыто.
- Манифест: имя, иконки, `display: standalone` — ставится как приложение.
- Офлайн работает последняя скачанная версия; для получения обновления нужен интернет.

## 5. Ошибки

| Ситуация | Поведение |
|---|---|
| Файл не PDF / битый | статус `Не удалось прочитать файл` |
| Зашифрованный PDF | `Файл защищён паролем` |
| Не 1 страница | `Ожидается одностраничный бланк` |
| Размер/содержимое не как у шаблона | `Неизвестный формат бланка: <что не найдено>` |
| Повтор трека | предупреждение, файл остаётся |
| Нет годных файлов | кнопки неактивны |
| Ошибка сборки PDF | сообщение над превью, загруженные файлы сохраняются |

Ошибка одного файла не мешает остальным.

## 6. Тестирование

- **`layout.ts`** (Vitest, юнит): число рядов и колонок по пресетам, перенос на новую
  страницу, 0/1/7/13 отправлений, ошибка невмещающегося пресета, влияние `fragmentScale`.
- **`extract.ts`** на реальных PDF из `data/` — ожидаемые реквизиты и трек для всех трёх
  файлов. `data/` в `.gitignore` (персональные данные), поэтому эти тесты пропускаются,
  если файлов нет. Плюс синтетическая фикстура, сгенерированная `pdf-lib` в тесте
  (без реальных адресов), — для CI и негативных случаев (не тот размер, нет трека,
  2 страницы).
- **`render.ts`, сохранность качества:** в выходном PDF фрагмент ссылается на картинки
  с теми же размерами (980×350, 848×1) и тем же фильтром (FlateDecode), что в исходнике.
- **`render.ts`, считываемость:** рендер итоговой страницы в растр 300 dpi (pdf.js в
  Node) → декодер (`zxing-wasm`) → штрихкод = трек, QR = содержимое QR исходника.
- **Ручная приёмка (выполняет пользователь):** печать в 100% на целевом принтере, рез,
  проверка сканером/телефоном и на почте.

## 7. Вне рамок

- OCR и сканированные бланки.
- Другие форматы бланков, кроме описанного (архитектура их допускает).
- Редактирование реквизитов вручную.
- Серверная часть, аккаунты, синхронизация.
- Экспорт таблицы в Excel/CSV.

## 8. Риски

- **Масштабирование при печати.** Если печатать «по размеру страницы», драйвер
  пересэмплирует штрихкод. Меры: подсказка в UI, фрагмент в натуральную величину.
- **Смена формата бланка генератором.** Меры: строгая валидация по шаблону, файл
  отклоняется с понятной ошибкой, а не печатается криво.
- **Нужен ли на фрагменте номер строки и примет ли почта пометку.** Неизвестно; флаг
  `printNumberOnFragment` в пресете.
